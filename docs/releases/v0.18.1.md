# v0.18.1 — pickup skill hardening from first real-run feedback

**TL;DR.** Three fixes to `/contract pickup` from the first real
end-to-end test. The skill prose was the difference between "works on
paper" and "behaves the way the docs claim." No API changes, no new
dependencies, no migration. Existing 0.18.0 contracts and `repos.yml`
configs keep working.

If you tried 0.18.0 and felt that pickup almost-but-not-quite did
what it said on the tin, this is the patch that closes the gap.

---

## What changed

### 1. Phase 2 now runs the full critic set inline, unambiguously

**What was wrong in 0.18.0.** The skill prose said "run critics in
parallel" but left enough ambiguity that the agent could draft the
contract, run only `critic-code-context` (the new dev-side critic),
and then suggest `/contract verify` as the next step. The first real
test produced exactly that: a card with Bucket A populated but no
edge-cases / security / instrumentation findings, and "next: run
`/contract verify`" at the bottom. That's the *old* two-step flow,
not pickup.

**What's fixed.** The skill is now explicit: pickup IS the verify. In
Phase 2 the agent runs:

- The deterministic validator (`scripts/validate.mjs`).
- The standard judgment critics selected per content — edge-cases,
  regression, security (unless purely cosmetic), instrumentation (if
  metrics/events), comms-completeness (if user-facing), platform-
  parity (if >1 platform), scalability (if data/server), perf-budget
  (if non-default budget).
- `critic-code-context` for the auto-fill proposals.

All in **one parallel Task batch**, and `.findings.md` +
`.findings.json` get written exactly as `contract-verify` would write
them. Two new anti-patterns explicitly forbid (a) suggesting
`/contract verify` as a next step and (b) producing a card with only
Bucket A.

### 2. Phase 1.0 preflight — no more silent degradation

**What was wrong in 0.18.0.** Running pickup without
`.manifest/repos.yml` produced a card with a casual note at the end:
"PM-channel automation and answer-watcher are inert — fine here." That
hid a real loss: the cross-repo regression scan, the cached auto-fill
catalog, the PM-channel routing, and the answer-watcher all depend on
`repos.yml`. The dev shouldn't be told it's "fine" by the agent — the
dev should be told what's actually missing and decide.

**What's fixed.** Pickup now starts with a preflight check (Phase
1.0) before fetching anything. If `.manifest/repos.yml` is missing:

> Heads up — there's no `.manifest/repos.yml` in this repo, so
> pickup is going to run with these pieces missing:
>
>   - Cross-repo regression scan — won't see related code in
>     other repos.
>   - Auto-fill from code (Bucket A) — limited to whatever I can
>     find in this repo on the fly; no cached event catalog / i18n.
>   - PM-channel automation — questions won't be routed to the
>     right tool because I don't know which channel your team uses.
>   - Answer-watcher — nothing to poll.
>
> Two options:
>
>   1. Set it up first — I'll run `/manifest setup`, ~30 seconds.
>      Then I'll resume pickup.
>   2. Skip and continue — pickup will still draft a useful
>      contract from the source, but those four features above
>      won't kick in.

If the dev picks (1), the agent invokes `/manifest setup` and resumes
pickup after it completes. If (2), the contract gets
`pickup.degradedMode: true` in frontmatter so the rest of the pipeline
knows not to expect the missing pieces. Same gate triggers when a
critical MCP isn't connected for the pasted source URL.

### 3. Card output reframed for someone reading their first pickup

**What was wrong in 0.18.0.** Sample output:

```
SC-001 — Voice dictation in the script editor · draft · medium · web

Bucket A — auto-filled from code (4) ✅
┌──────────────────────┬─────────────────────────────────────────────┐
│ Item                 │ Value                                       │
├──────────────────────┼─────────────────────────────────────────────┤
│ Text insertion API   │ editor.tf.insertText() via useEditorRef()   │
│ Toolbar wiring       │ ToolbarTypes → ToolbarMapper → index.tsx    │
│ Punctuation commands │ Reuse applyPunctuationCommands (extract …)  │
│ Analytics shape      │ BUTTON_CLICK + action/screen pattern        │
└──────────────────────┴─────────────────────────────────────────────┘
```

Fine for someone who already knew the codebase. Opaque if you don't.
A new team member, a stakeholder, or anyone reading the contract
later sees random IDs and file paths with no context.

**What's fixed.** Card layout rules now:

- **Feature title in plain English leads.** The contract ID
  (`SC-001`) drops to a small metadata row, not the title.
- **Bucket headlines in plain English.** "Agent filled in 4 from your
  code" instead of "Bucket A — auto-filled from code (4)". Bucket
  letters stay in the JSON findings for tooling but don't surface in
  the human card.
- **Every technical reference gets a plain-English line above it.**
  `editor.tf.insertText() via useEditorRef()` is the receipt; the
  prose ("How the new text gets inserted into the editor — same
  pattern as the existing draft handler") is the answer.
- **File paths drop to `↳ refs:` footnotes.** Table columns made
  refs feel load-bearing; footnotes signal "auditable detail."
- **Jargon gets a parenthesized gloss the first time it appears.**
  "AnalyserNode tap (a tiny audio-meter that doesn't store audio)"
  on first mention; terse on later mentions.
- **Question IDs (`Q-1…Q-4`) never appear in the human card.** They
  live in the contract frontmatter and the `qa.md` sidecar.

Same information density; more accessible default.

## Upgrade

Two commands:

```
/plugin marketplace update manifest
/plugin install manifest@v0.18.1
```

Or, if you track the tag-based install:

```
/plugin install manifest@manifest
```

…will pull v0.18.1 once published.

No config changes required. Existing `repos.yml` entries keep
working. Contracts authored under 0.18.0 don't need migration — the
new preflight only triggers for new pickups.

---

## What this is NOT

- Not a security or correctness fix in the validator / critics / CI
  workflows.
- Not a change to the contract `.md` format or the critic protocol.
- Not a new entry point or new subcommand.

This is purely skill prose hardening. The agent's behavior catches
up to what the 0.18.0 docs already promised.

---

## Test the difference

Re-run pickup on the same task that gave you the confusing 0.18.0
output. You should see:

1. If you have no `repos.yml`: the agent stops at the preflight
   and asks before proceeding. The 0.18.0 silent-degrade ending
   ("fine here") is gone.
2. The card leads with your feature in plain English, not the
   `SC-NNN` ID.
3. Bucket items have a plain-English line per item with `↳ refs:`
   underneath, not table columns.
4. The "Next steps" line does NOT suggest `/contract verify`. It
   suggests review/edit, the fix loop, sending PM questions,
   `/contract promote`, or `/implement`.
